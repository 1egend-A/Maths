### 3.2 `p0_load.m` —— 读取四个附件

```matlab
D = p0_load(cfg);
```

**意义**：把四个格式各异的 xlsx 变成一个**统一、干净、无歧义**的结构 `D`，并落盘 `out/data.mat`。这是全项目唯一读原始文件的地方——其他地方一律从 `D` 取数。

**返回结构 `D`**：

| 字段 | 尺寸 | 含义 |
|---|---|---|
| `D.day144.time` | 144×1 string | **附件1** 的时段标签，已归一化为 `00:10 … 23:50, 00:00+1` |
| `D.day144.price` / `.load` / `.pv` | 144×1 double | 附件1 的电价 / 小区负载 / 光伏预测功率 (kW) |
| `D.actual.dates` | 365×1 datetime | 2025-01-01 ~ 2025-12-31 |
| `D.actual.load` | 365×144 | **附件2** 实际小区负载 (kW) |
| `D.actual.pv` | 365×144 | **附件2** 实际光伏功率 (kW) |
| `D.actual.price` | 365×144 | **附件4** 全年电价 (元/kWh) |
| `D.fc.dates` | 1460×1 datetime | **附件3** 预报发布日期（已向下填充） |
| `D.fc.issue` | 1460×1 string | 预报时刻：`0:00` / `6:00` / `12:00` / `18:00` |
| `D.fc.pv` | 1460×24 | 每次预报的未来 24 小时光伏功率 (kW) |
| `D.fc.horizon` | 1×24 | 预报步长标签 `1:24`（对应 `预报1小时` … `预报24小时`） |
| `D.slots.label` / `.minutes` | 144×1 | 统一时段标签 / 自当日 00:00 起的分钟数 |
| `D.meta.*` | — | 来源路径、读取时间、各表规模、日期区间 |

**内部处理的两个坑（都在这个文件里解决掉）**：

1. **附件2 / 附件4 的第 1 行不是纯表头**。第 1 列是 `日期\时间` 字符串，第 2~145 列是 `0.0069 / 0.0139 / 0.0208…` 这类**「日分数」**（即 00:10 / 00:20 / 00:30）。用 `readmatrix` 直接读会把这一行当数据吞进去。
2. **附件1 的时间列是混合类型**：前 60 个被 MATLAB 解析成日分数，后 84 个仍是字符串，末行是 `'0:00+1'`。统一由 `timeLabel()` 归一化。

**主要局部函数**：`readTimeMatrix`（读"日期\时间+日分数"格式表）、`timeLabel` / `minsLabel` / `minutesOf`（时间标签三段式转换）、`fillForwardDates`（附件3 合并单元格向下填充）、`cells2mat`（cell→double，遇非数值**直接报错而非静默变 NaN**）。

### 3.3 `p0_check.m` —— 验收（双路互证 + 不变量 + 守恒律）

```matlab
ok = p0_check();      % ok = true 表示全部通过
```

**四组检查**：

| 组 | 内容 |
|---|---|
| 1. 双路互证 | `readcell` 路径 vs `readmatrix`+显式 `Range` 路径，7 项逐元素比对 |
| 2. 结构不变量 | 144 时段标签序列精确匹配、365 天日期连续无缺、附件3 的 365×4 时刻完整 |

**当前结果**：全部 PASS。双路偏差 `0.000e+00`；功率平衡残差 `9.1e-13 kW`；同时充放 0 时段。

### 3.4 `soc_sim.m` —— 储能 SOC 递推引擎


**意义**：把"充放电功率序列"翻译成"SOC 轨迹"。全项目所有涉及 SOC 的计算都必须走这个函数，**不允许各自手写递推公式**——那是口径分裂最常见的来源。

### 3.5 `day_lp.m` —— 单日 LP（Q1 雏形，Q2–Q4 复用）

```matlab
[g, c, d, cost, info] = day_lp(price, load, pv, S_start, cfg, S_end);
```

**意义**：**整个项目最核心的可复用组件**。Q1 用它；Q2 在它外面加"预测层 + 紧急购电执行层"；Q3 在它外面加"滚动调整 + 非对称罚则"；Q4 在它外面套"场景/CVaR"。**求解器本身只有一个。**

**模型**（决策变量 `x = [g(1..n); c(1..n); d(1..n)]`，n = 144）：

```
min  Σ_t price_t · g_t · dt
s.t. 功率平衡    g_t + d_t − c_t = L_t − PV_t
     SOC 递归    S_t = S_start + Σ_{s≤t} (c_s·η − d_s/η)·dt
     SOC 边界    S_min ≤ S_t ≤ S_max
     功率上限    0 ≤ c_t, d_t ≤ P_max,  g_t ≥ 0
     （可选）日末 S_n = S_end
```

| 参数 | 含义 |
|---|---|
| `price`/`load`/`pv` | 该日 144 个时段 |
| `S_start` | 当日 0:00 的 SOC (kWh) |
| `S_end` | 日末 SOC 目标；**传 `[]` 表示不约束** |
| **返回** `g`,`c`,`d` | 最优购电 / 充电 / 放电功率 (kW) |
| **返回** `cost` | 最优日购电费 (元) |
| **返回** `info` | `flag` / `msg` / `nVar` / `nCon` / `term` / `effConv` |

> **为什么不需要 MILP**：`η = 0.90 < 1`，同时充放 1 kWh 净损失 0.1 kWh，故 LP 松弛的最优解天然满足 `c_t · d_t = 0`。已在验收中逐个时段验证（冲突 0 个），**纯 LP 即可，无需 0-1 变量与 big-M**。这直接绕开了本队"编程工程"的弱项。

## 4. 七条口径：已定 3 条 / 待定 4 条

> 口径 = 「题目没明说、但不同理解会给出不同数值答案」的建模选择。
> 它们的共同特征是：**选错了不报错，只是数字全错**。所以必须显式声明、全文统一。
>
> **状态**：口径 **1 / 4 / 5 已定**（1、4 是必须二选一的物理约定；5 是实证标定而非常规选择）；
> 口径 **2 / 3 / 6 / 7 待定**——下面给出的是**比较材料与倾向性意见**，
> 不是决议。真源见 `p0_config.m`（首部有横幅）。

### 4.1 口径 1：效率计量侧 ⚠️

| | **交流侧计量（本队采用，`effConv='ac'`）** | 直流侧计量（`'dc'`） |
|---|---|---|
| `c_t` 含义 | 从电网取来用于充电的功率 | 进入电池的功率 |
| `d_t` 含义 | 送到负载的放电功率 | 从电池取出的功率 |
| 功率平衡 | `g+e+PV+d = L + c` | `g+e+PV+d·η = L + c/η` |
| SOC 动态 | `(c·η − d/η)·Δt` | `(c − d)·Δt` |

**选交流侧的理由**：题目给的 `P_max = 5000 kW` 与容量按电表（交流）侧理解更自然。

> **本次修正**：路线图原稿把两式**混用**了（式(1) 用直流侧、式(2) 用交流侧），已在路线图中修正。两式各自自洽，但配错会算错费用。

### 4.2 口径 2：日末 SOC　⚠️ **待定**（以下是比较材料，不是决议）

用三种取值各跑一遍 1 月（S₀ = 6000，实际负载/光伏 + 附件4 电价）：

| 取值 | 2/1 0:00 SOC | 1 月总费用 |
|---|---|---|
| `free` 不约束日末 | **1200 kWh** | 1,722,104 元 |
| `close` 日末回到当日起点 | **6000 kWh** | 1,716,292 元 |
| `fixed` 日末固定 6000 | **6000 kWh** | 1,716,292 元 |

**两点值得写进论文（但选哪条仍须三人当面定）**：

1. **`free` 是退化的，而且反而更贵。** 每天独立最优且不约束日末 → 第一天就把电池放到下限 1200，之后永远趴在下限，丧失后续套利能力 → 1 月**多花 5,812 元**。这是「**逐日独立最优 ≠ 全局最优**」（多日耦合）的直接证据，可做论文对照实验。
2. **倾向性意见**：`close` 或 `fixed`，此时 2/1 起始 SOC 恰好 = 6000，链式依赖自然闭合，也与"题目只给 6000 一个初值"的意图一致。

> ⚠️ **误用 `free` 会让 Q2/Q3 从 1200 kWh 起步，全年结果全部作废。**
> 但"不要 `free`"不等于"就用 `close`"——选 `close` 还是 `fixed` 是队内决策，代码里的 `'close'` 只是占位。

### 4.3 口径 3：调整量结算粒度（Q3 用）　⚠️ **待定**

`slot` = 逐 10 分钟比计划；`day` = 按全天总量比计划。**当前设 `slot` 只是占位**，Q3 开工时需做敏感性对照，并由队内定死——它直接决定 0.5×/1.5× 非对称罚则的金额。

### 4.4 口径 4：时段归属　✅ **已定**

第 i 个数据点 = 区间 `(t_{i−1}, t_i]` 的**右端点**，区间是结算与执行的单位。
即标签 `00:10` 表示 **00:00–00:10 这 10 分钟**。

> 背景：附件时间点整体与 `result1` 的区间标签错位一格，且 `result1` 与 `result2` 的末段标签互相矛盾（`0:00+1-0:10+1` vs `0:00-0:10+1`）。本口径为显式声明，并用守恒律反推验证。

### 4.5 口径 5：附件3 预报区间归属　✅ **已定（实证标定）**

「预报 k 小时」= **发布时刻起算的第 k 个小时**；行内 24 列是从发布时刻起算的连续 24 小时，**会跨到次日**。

- `calib_fc_offset.m` 用附件2 全年实际光伏反向标定（21876 样本）：偏移 `+1` 合并 RMSE **763.78**，远优于字面读法 `0` 的 **1797.08**；四个发布时刻各自 15/15 个步长全部支持。
- 这是**实证标定**而非口径选择——数据本身指向唯一答案，故列为已定。

### 4.6 口径 6：附件5 模板填充规则　⚠️ **待定**
