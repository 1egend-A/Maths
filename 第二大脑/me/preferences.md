# 规矩

## 一、做作业

- **三色约定**：蓝色 = AI 辅助内容，红色 = 人工批注，黑色 = 本人手写。
- **每 5 行插一处人工批注**；实操按「每个论述段落后一条」执行，余量最大。
- **批注风格取中间档**：「半书面 + 少量第一人称」，扣住具体段落；不要纯说明体，也不要过度口语。
- 每条批注必须扣住该段的具体内容，禁止「这一步很关键」这类通用句。
- **文末单列「AI 使用说明」**：工具名称 + 对应题目/章节 + 输入给 AI 的完整提示语。
- 提示语**不要照录口语原话**，要拟成分条、严谨、不跳步的「完整要求」；标签如实写成「本次作业向 AI 提出的完整要求」，别写「原文照录」。
- 只交 PDF，文件名按课程要求；页脚居中「第 N 页 / 共 M 页」。

## 二、写报告与交付

- 选股报告**只做 MD + HTML**，不做 Excel（除非明确要）。
- 每只标的都要**逐只深度分析**，禁止骨架模板与空章节；宁可少几节，不留空壳。
- 「精选 / 排名 / 持仓」一律按**综合得分 factor_score 降序**，不按技术分排序。
- 止损价 / 止盈价后必须紧跟**相对报告基准价**的涨跌幅；基准价永远是「选中日收盘价」，选股与复盘同一个数。
- 必须披露**持有期终点日期**（按交易日历核算，不手数）与**止盈位隐含的设计持有天数**。
- 剔除理由必须能在已验证结论里找到出处；**「量能不足 / 缩量」永远不许当剔除理由**。
- HTML 报告页脚写**页面渲染时间**，便于判断是否看到最新版本。
- 每条数字断言写进论文前，先跑脚本核一遍；机制必须由数据推出来，不能由常识推出来。

## 三、跑脚本与动数据

- **A 股三大铁律**（永久有效）：
  1. Agent 禁止串通——审查 Agent 必须盲审，不被告知其他结论。
  2. 绝对禁止未来函数——只用该时点之前的数据，财务数据按披露日筛选。
  3. 参数透明——权重/阈值/窗口集中在独立参数文件，记录取值、理由、可调范围与修改记录。
- **工作流与账本写入一律等明确指令**，不做「顺手跑一下看看」；只读的查询与报告可以主动做。
- 未点名「BOLL 工作流」时，默认跑旧工作流。
- 消息面（减持/立案/业绩）以官方数据接口为准，搜索结果摘要只当线索。
- **每轮改完必须重跑前几轮的验证脚本**，否则回归会一直躺着。
- 动工前先读懂已有实现（局限性、优缺点、待优化点）再动手改。
- 校验类数字必须**双向**：既要「新 ⊆ 旧」，也要「旧 − 新 = 0」。

## 四、协作与范围

- 范围纪律：说「做预处理」就只做预处理；预测方法、求解、交付都不属于预处理。
- 需要拍板的口径**不给默认值**——标【待定】并写明「这不是决策」。
- 含数字的中间产物不要删，把免责说明写进**生成脚本**，再配一份 README 说明哪些数字可引用。
- 团队协作中，宁可交窄而准的东西，不替别人把决策空间填了。
- 任务完成后的固定结束语：**「大爷！任务已完成」**。

## 五、与 AI 协作与留痕

- 接手项目先读该项目的记忆/档案，尤其标「接手先读」的——里面写着上次停在哪、哪些结论已作废。
- 一个任务一个会话；长会话背着全部历史干活，既贵又容易跑偏。
- 改动留痕：Ledger 追加一行，任务目录放 plan + 工作报告；不说「推送」就不提交、不推送。
- 记忆只记非显而易见的，能从仓库读出来的不进记忆；每次增删改后立即整目录镜像备份。
- 验证阶段明确要求 AI「找能让这个结论失效的证据」，否则它会顺着你的假设补论证。

## 六、绝对铁律：有价值的工作必须回填本库

- **只要完成价值较高的工作**——项目交付、竞赛、策略迭代、工具链或方法上的突破、重大决策——就必须提取经验精华（背景 / 做法 / 结论 / 坑 / 可复用规则），写进本库对应文件。
- **主动做，不等提醒**；不问「要不要记」，直接判断落点：项目过程进 `projects/`，方法教训进 `decisions/`，工具进 `toolchain/`，习惯进 `me/preferences.md`，当月大事进 `log/timeline.md`。
- 只追加、不改写旧记录；新条目带日期；已证伪的结论要标「仅历史参考」。
- 写完提交并推送。**这是长期义务，优先级高于「任务结束」本身。**
