# 零号审稿人（reviewer-zero）

## 一句话

面向学术论文的自动审稿智能体：三个「审稿人角色」并行给意见，再由主编角色仲裁，最后按两套评分尺子出分。网页版可直接使用，支持 PDF 上传、复跑对比、分享链接。

## 架构

- **三角色 + 质检**：统计派 / 方法派 / 主编，另有 QC 门禁。
- **七阶段流水线**：preflight → provider → analyze → qc → arbitrate → gate → aggregate。
- **两把尺子**（分母都是 100，但刻度不同、**不可比**）：
  - 期刊尺子：novelty 20 / rigor 20 / evidence 20 / result 15 / writing 15 / reproducibility 10（2026-10-31 起六维）。
  - 竞赛尺子：30 条条款，rigor 30 / evidence 30 / writing 20 / novelty 10 / repro 10，纯关键词判定、零模型调用。
  - 第三套：**形式尺子**（图文格式排版审美，40 分），由 PDF 版面几何确定性打分；内容 60 分由旧五维桥接。与前两把分母不同，报告里明确写不可比。
- 规则版与模型版双通道；规则版 3 毫秒出结果，模型版 8–10 秒出 9 条意见。

## 记录制度（硬要求）

两层留痕，缺一不可：
1. `Ledger.md` 追加一行：日期 / 类型 / 任务 / 涉及文件 / 达成 / 验证 / 备注。
2. `tasks/<任务名>-日期/` 放 `plan.yaml` + `工作报告.md`。

改动一律不提交不推送，除非明确说「推送」。实际节奏是每轮收尾单独说一句才 commit + push。

## 关键发现（都做过量化核验）

### D1 有效性评测：负结果

- 978 篇、22.9 秒、零模型调用。主题级 Jaccard 宏平均 0.1911，**打乱配对零模型 0.1935**——比随机还低 0.2 个百分点。
- 机制：978 篇只产出 67 种不同的主题集合（多样性 6.9%），本质是 8 条固定规则在套模板。
- **三条红线**：离线数字不得写进参赛材料；不可与「某大模型 15–16%」并列（口径完全不同）；零模型必须同时报「均匀抽样」与「打乱配对」两种。
- 附带产物：人类局限里 23.9% 属于「结果分析」，而五维尺子里没有这一维 ⇒ 这是补第六维的直接证据（该数字可引用，覆盖率数字不可引用）。

### 52 篇语料校准（形式六维）

- 自建 52 篇 / 27 刊 / 10 门类语料库（T1 43 + T2 9），刻意保留 T2 与数据集/软件类异形体裁。
- 实测：均值 69.4、**中位 59**、30/52 被「desk-reject 封顶 59」；体裁中位差 81.2 vs 59；T1/T2 无区分（δ=0.129，不显著）。
- 结论：形式维测的是**体裁与版式惯例**，不是水平；审美维 52/52 满分、方差 0，等于没测。
- 复核新查出 6 个缺陷：图注正则区分大小写（`FIG.` 认不出）、「29/52 零表格」混了三种原因（其中 13 篇是被截断）、某条门禁是死规则（依赖的字段根本不产出）、报告卡硬编码 60+40、护栏脚本不覆盖新尺子、60 分内容维完全没校准。

### 前端优化（8 项）

线上基线快照 + 本地 3901 + Playwright A/B 的做法。三批 8 项全修（断言从 3/7 → 7/7、1/4 → 4/4、1/6 → 6/6），第四批补服务端后共 34 条断言全绿。

典型 bug：模型失败被渲染成「预检拒绝」；保存配置时把 URL 覆盖值写进本地存储（看一眼演示链接就永久降级）；连选两份 PDF 的并发竞态（后落地的旧文件覆盖新正文）；扫描件判定了却走不到纯图通路。

## 最大的坑：线上跑的不是仓库里那份

- 线上启动器按「overlay 目录 > 包内置文件」的顺序加载，而 overlay 目录被 `.gitignore` 排除 ⇒ **真正在跑的核心代码既不在仓库、也抓不到**。
- 由此产生一条长期误判：以为「整目录重发布会打坏链接」。实际有热切换通道（push-code / reload），失败自动回滚；真正缺的只是 token 和当前源码。
- 「推到 GitHub」≠「队友拿到」≠「线上生效」，三件事要分开说。

## 教训

1. **标定实现 ≠ 部署实现**。复核必须把部署那套代码塞进沙箱跑，不能用别的库近似——本项目因此栽过 4 次。
2. **满分相同 ≠ 刻度相同**。两把尺子分母都是 100，但维度不同，分数不可比；判可比性要看版本号，不是看分母。
3. **新增的键只在该尺子里存在时**，先全局搜索它被读了几次，否则会出现「意见渲染出来、永远打不了分」。
4. **别把队友改写的同名文件当原文**：同一文件在两条分支上是两份不同内容，以自己分支为原文。
