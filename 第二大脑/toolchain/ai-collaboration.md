# AI 协作

## 记忆怎么组织

- **两层**：`MEMORY.md` 是索引（一行一条），每条记忆单独一个文件，带 `name / description / type`。
- **type 只有四种**：user（我是谁）、feedback（该怎么干活）、project（项目状态）、reference（外部资源指针）。
- **检索靠 description 匹配**，所以 description 要写成「什么时候该读我」，不是内容摘要。
- **写之前先查重**：同一件事已有文件就改它，不新建。过期或已被证伪的记忆要删，别留着误导。
- **只记非显而易见的**：代码结构、git 历史、文件路径这类能从仓库读出来的，不进记忆。
- **备份铁律**：每次增删改记忆（含索引）后，立刻把整个目录镜像到 `.claude` 之外的位置——放在 `.claude` 里等于没有备份。镜像必须带删除语义（`/MIR` 或等价），不能只追加覆盖。
- 用 `cp -rf` 做镜像时的坑：目标目录已存在时会把源整个塞进去，变成 `DST/memory/…`，看起来同步了其实没有。必须写 `cp -rf "SRC/." "DST/"`，事后用 `diff -rq` 确认全静默。

## 会话怎么开

- **接手一个项目，先读该项目的记忆文件**，尤其是标了「接手先读」的；里面有前一次停在哪、哪些结论已作废。
- **工作流、账本、批量脚本，一律等明确指令再跑**；只读的查询和报告可以主动做。
- **长会话有害**：一个任务一个会话，别背着几十轮历史干活。
- 改动留痕：Ledger 追加一行（日期 / 类型 / 任务 / 文件 / 达成 / 验证），任务目录放 plan + 工作报告。
- 提交与推送只在明确说「推送」时做，不默认推送。

## 人在环上的位置

- AI 负责：实现、穷举、批量验证、找反例、一致性审计。
- 人负责：定问题、定口径、定「什么算通过」。需要拍板的口径不给默认值，标【待定】。
- **AI 会顺着你**：你提一个漂亮假设，它能补一整套自洽论证。所以验证阶段要明确要求它「找能让这个结论失效的证据」。

## 手机与远程

- 官方 Remote Control 让手机当窗口、真正跑在本机会话上；但**只支持 claude.ai 付费账号登录，不支持 API key**，终端一关就离线。
- 云会话跑在隔离 VM 里，碰不到本机文件与局域网。
- 兜底：Windows OpenSSH + 手机 SSH 客户端；断线保活用 WSL2 + tmux；外网走 Tailscale / WireGuard，别裸暴露端口。
- 会话内定时任务只在 REPL 空闲时触发、进程退出即丢，要留缓冲窗口。

## 本机运维

- 杀毒软件可能拦截 CLI 自动更新，表现为更新反复失败；把安装目录加入信任区，或设环境变量关闭自动更新。
- 更新失败后先看是不是被安全软件拦了，再怀疑网络。
